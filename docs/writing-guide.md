# 용어와 문장 기준

이 저장소의 문서, 주석, 테스트 이름, 스크립트 출력에 쓰는 말을 정한 문서입니다. 같은 것을 문서마다 다른 이름으로 부르지 않고, 문장마다 누가 무엇을 하는지가 보이게 쓰는 것이 목적입니다.

새 문서를 쓰거나 문장을 고칠 때 이 문서를 먼저 봅니다. 여기에 없는 용어가 필요하면 이 문서에 먼저 추가한 뒤에 씁니다.

## 1. 결함과 취약점

두 말을 구분해서 씁니다.

- **결함**: 코드나 설계의 잘못입니다. 원인을 말할 때 씁니다.
- **취약점**: 결함 때문에 공격이 통하는 상태입니다. 결과를 말할 때 씁니다.

| 결함 | 결함 (코드의 잘못) | 취약점 (그 결과) |
|---|---|---|
| 1 | 컨트롤러에 `@UseGuards`를 붙이지 않음 | 전체 신청 목록이 인증 없이 열림. 인증 누락 (CWE-306) |
| 2 | 경로의 앞부분만 비교하는 공개 조건 | 수강생 명단이 인증 없이 열림. 인증 누락 (CWE-306) |
| 3 | 헤더와 request body를 서버 로그에 출력 | 로그를 읽은 사람에게 비밀번호와 토큰이 노출됨 (CWE-532) |
| 6 | 검색어를 SQL 문자열에 이어 붙임 | SQL 인젝션 (CWE-89) |
| 8 | 신청자를 request body에서 읽음 | IDOR (CWE-639) |

- 결함은 "고치다"라고 쓰고, 고친 결과에는 "수정"을 붙입니다(수정 태그, 수정 커밋). "결함을 막다", "결함을 수정하다"는 쓰지 않습니다.
- 항목 번호(결함 1), 태그 시점(결함 상태), 코드의 잘못을 가리키는 말(결함이 있는 코드)에는 "결함"을 씁니다.
- 진단 보고서의 구성 요소 표에서 결함이 있는 칸은 이 순서로 적습니다: 누가 무엇을 하는지, 그것이 결함이라는 것, 그 결과 생기는 취약점.

  > 핸들러가 이 값을 클라이언트가 보낸 request body에서 읽습니다. 이 부분이 결함이고, 그 결과 다른 사용자의 이름으로 신청할 수 있는 취약점(IDOR)이 생깁니다

## 2. 사람을 부르는 말

| 쓰는 말 | 쓰지 않는 말 | 설명 |
|---|---|---|
| 요청한 사람 | 누가 요청하면 | 요청을 보낸 사용자입니다. 값이 어디서 오는지를 말할 때만 "토큰의 사용자"라고 씁니다 |
| 신청자 | 신청의 소유자 | 신청에 이름이 들어간 사용자입니다 |
| 피해자 | 이름이 쓰인 사람 | 처음 나올 때 한 번 "이름이 도용된 사람(피해자)"이라고 풉니다 |
| 본인의 | 자기 | 학생이 자신의 신청, id, 정보를 볼 때 |
| 담당 강의 | 자기 강의 | 강사와 강의의 관계 |
| 다른 사용자의 | 남의 | |
| 서버에 접근할 수 있는 사람 | 서버의 출력을 볼 수 있는 사람 | 로그는 "읽다"라고 씁니다 |
| 공격자 | 토큰을 얻은 사람 | 침해나 유출의 결과를 쓰는 사람. 누구인지 더 좁힐 수 있으면 그 말을 씁니다(로그를 읽은 사람) |

접근통제 용어인 "소유자"는 그대로 씁니다(소유자 확인, 객체의 속성(소유자)).

## 3. 하는 일을 부르는 말

| 쓰는 말 | 쓰지 않는 말 | 설명 |
|---|---|---|
| 신청하다 / 신청을 받다 | 신청 요청, 신청을 생성하다 | 학생은 신청하고 서버는 신청을 받습니다. "신청 생성"은 기능의 이름(제목, 테스트 이름, 표의 칸)으로만 씁니다 |
| ○○의 이름으로 신청되다 | ○○의 신청으로 저장됨 | "저장되다"는 값이 DB에 남는 것을 말할 때만 씁니다 |
| 취소 / 삭제 | | `DELETE /enrollments/:id`는 취소, DB에서 직접 지우는 것은 삭제 |
| 추가하다 | 더하다 | 테스트, 필드, 번호를 넣을 때. 셈("1을 더하는")과 "~에 더해"는 그대로 씁니다 |
| 변경하다 | 바꾸다 | 비밀번호 |
| 적용되다 | 돌다 | Guard |
| API를 띄우다, 스크립트를 실행하다 | 태그를 띄우다 | 띄우는 것은 태그의 API입니다 |
| 폐기하다 | 버리다 | 패킷 |
| (API가) 요청에 401로 응답하다 | 요청이 401로 끝나다 | 상태 코드는 요청이 아니라 응답에 붙습니다 |
| 변경하거나 삭제하다 | 바꾸거나 지우다 | 데이터를 고치는 일을 통틀어 말할 때. "취소"는 신청을 취소하는 기능의 이름입니다 |
| 확인하다 | 검사하다 | 서버가 요청이나 값을 보는 일(정원 확인, 권한 확인). 도구가 코드를 보는 일은 "검사"라고 씁니다(타입 검사, 린트) |
| 정상으로 동작하다 | 맞게 동작하다 | |
| ~을 뜻합니다 | ~을 가리킵니다 | 용어의 뜻을 말할 때 |

## 4. 보안 용어와 DB 용어

| 쓰는 말 | 쓰지 않는 말 | 설명 |
|---|---|---|
| 입력값 검증 | 입력 검증, 형식 검증 | DTO와 전역 `ValidationPipe`가 받은 값을 확인해 틀리면 400을 내는 일 |
| 클라이언트 측 입력값 검증 | 화면의 검사 | 브라우저의 화면에서 하는 입력값 검증 |
| 클라이언트가 보낸 request body | 검증되지 않은 request body | request body는 입력값 검증을 거칩니다. 빠진 것은 그 값이 토큰의 사용자와 같은지 확인하는 일입니다 |
| 앱의 접근통제 없이 | 접근통제 없이 | 로그에는 서버 쪽의 접근통제가 따로 있으므로 "앱의"를 붙입니다 |
| 웹 서버가 침해되다 | 웹이 침해되다 | 무엇이 침해되는지를 적습니다 |
| 사칭하다 | ~인 것처럼 요청하다, 그 사용자의 요청을 보내다 | 다른 사용자의 토큰이나 비밀번호로 그 사용자의 권한을 쓰는 것 |
| 위조하다 | | 서명 키로 토큰을 만들어 내는 것. 얻은 토큰을 그대로 쓰는 것은 사칭입니다 |
| 피해 범위 | | 침해됐을 때 영향을 받는 사용자와 데이터의 범위 |
| 계정 탈취 | | 다른 사용자의 계정을 넘겨받는 공격의 이름. 사칭은 얻은 토큰이나 비밀번호로 그 사용자의 권한을 쓰는 행위입니다 |
| 접근통제 | 접근 통제 | 붙여 씁니다 |
| 흐름 | 길, 경로 | 요청이나 값이 지나가는 것. "경로"는 API가 받는 주소(메서드와 URL)에만 씁니다 |
| 기밀성을 침해하다 | | 확인한 속성만 적습니다. 결함 6은 읽기만 확인했으므로 무결성은 적지 않습니다 |
| tautology 기반, UNION 기반 | Blind SQLi | `' OR …`로 조건을 항상 참으로 만드는 검색어는 결과가 응답에 그대로 나오므로 Blind가 아닙니다 |
| SQL 문자열 | 쿼리 문자열 | "쿼리 문자열"은 주소의 `?` 뒤쪽 부분에만 씁니다 |
| 외래 키 제약 조건(참조 무결성) | 외래 키 제약 | |
| 고유 제약 조건 | 유일 제약 | |
| `userId` 필드 | `userId` 값 | request body 안의 항목을 가리킬 때 |
| Ingress, Egress | 받는 쪽, 보내는 쪽 | 네트워크 정책의 방향은 영문으로 씁니다 |
| 기댓값 | 기대 | 테스트 |

- 표준 용어는 풀어 쓰지 않습니다: 시행 지점(PEP), 판단(PE), RBAC, ABAC, IDOR, request body.
- 접근통제 용어가 코드의 무엇인지는 처음 나올 때 괄호로 한 번 밝힙니다: 객체 선언(`@Authorize`의 `resource`).
- 이 저장소의 서비스는 "세미나 신청 서비스"라고 부릅니다. "이 데모의 도메인"이라고 쓰지 않습니다.

## 5. 문장

| 피하는 꼴 | 예 | 대신 |
|---|---|---|
| 주어가 없는 문장 | request body에서 옵니다 | 누가 하는지를 적습니다. "핸들러가 이 값을 request body에서 읽습니다" |
| 주어와 서술어가 맞지 않는 문장 | 채택하지 않은 이유는 `userId`가 남는 것입니다 | "…남기 때문입니다" |
| 명사로 끝나는 문장 | ~한 경우입니다, ~에 관한 것입니다, 대상이 됩니다 | 무슨 일이 일어나는지를 동사로 적습니다 |
| 가리킬 것이 문장 안에 없는 말 | 결함은 여기입니다, 그 값, 그 계정, 그동안 | 무엇인지, 언제인지를 이름으로 적습니다 |
| 결과가 빠진 문장 | 관리자를 사칭할 수 있습니다 | 누가, 그래서 무엇을 할 수 있는지까지 적습니다. "로그를 읽은 사람은 관리자를 사칭해 관리자만 볼 수 있는 전체 신청 목록을 조회할 수 있습니다" |
| 줄여서 뜻이 빠진 말 | 태그의 것, 객체가 됩니다, 화면의 검사 | 실제로 일어나는 일을 풀어 적습니다 |
| 수동 꼴 | 로그는 넓은 범위에서 읽히고 오래 보관됩니다 | 사람을 주어로 둡니다. "서버에 접근할 수 있는 사람은 앱의 접근통제 없이 로그를 읽을 수 있습니다" |
| 범위가 흐린 말 | 보통 오래 보관합니다 | 단정할 수 있는 사실을 적습니다. "로그는 요청이 끝난 뒤에도 남습니다" |
| ~만 보면, ~만 봐서는 | 상태 코드만 봐서는 알 수 없습니다 | "상태 코드만으로는 공격인지 알 수 없습니다" |
| 비유 | 토큰이 밖으로 나갑니다 | "삽입된 스크립트가 토큰을 읽어 외부로 보낼 수 있습니다" |

- 예로 드는 값은 이 서비스에 있을 만한 것을 씁니다. 결과가 0건이어야 하는 검색어는 "암호학"입니다.
- "없는 아이디"가 아니라 "존재하지 않는 아이디"라고 씁니다.
- 한계는 '한계' 절에, 하지 않은 것을 사실로 적습니다.
- 흐름도의 범례는 무엇이 그 색인지를 적습니다. "초록은"이 아니라 "초록색 상자는", "빨간색 화살표는"이라고 씁니다. 그림의 칸은 "상자"라고 부르고, "칸"은 표에 씁니다.

## 6. 문장을 고칠 때

1. 고칠 줄이 든 표나 문단 전체를 읽습니다.
2. 같은 내용을 적은 다른 문서의 문장을 찾아 같은 말로 맞춥니다. 보고서의 분류, 절 제목, 원인 코드 절에 이미 쓴 말이 있으면 그 말을 씁니다.
3. 낱말만 바꾸지 않고 문장을 다시 씁니다.
4. 코드 블록에 옮겨 적은 출력과 명령, 태그 시점의 코드를 옮긴 diff는 고치지 않습니다.
